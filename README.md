**中文** | [English](README.en.md)

## 1.1 它长什么样：一个小工具，不是一个后台

- **窗口**：默认 780 × 520，就是普通桌面小工具那种体量；需要更多空间自己放大。
- **导航**：顶部一排小标签（首页 / 历史 / 恢复 / 设置），右侧一行显示"正在保护 D:\…"，不占左侧宽度。
- **首页**：保护状态两行 + "最近变化"表格 + 两个按钮（查看历史 / 找回之前的状态）。
- **历史**：一张表（时间 / 类型 / 文件）+ 右侧"这一条的详细情况"。
- **恢复**：一行工具栏 `时间点[▼] → 恢复到[▼] [当前状态] [⇄] [确认恢复]`，
  下面是**一个迷你文件浏览器**——显示所选时间点的真实文件结构（📁/📄），双击进入目录、
  勾选文件加入**恢复集合**；底部 `全选 / 取消全选 / 反选`（只作用于当前列表）+ `已选 N 个文件`。
- **自定义恢复**：恢复集合可以**混合来自不同时间点的文件**——
  在 A 时间点挑 `Documents\a.txt`，换到 B 时间点再挑 `Projects\test.json`，
  最后一次性恢复，每个文件各自用它被挑中时那个时间点的版本。
- **自定义删除**：勾选文件后点「标记删除」，执行时把它删掉（行上会写「（将删除）」）。
  删除与恢复可以放进**同一次执行**：`a.txt` 恢复到某个时间点的版本，同时 `b.txt` 被删除。
  删除前会先留存内容副本、并创建安全点，**删错了点「撤销这次恢复」即可整体还原**。
- **设置**：保护文件夹 / 保存历史 / 磁盘空间 / **存储位置** / **清理变化记录** 五组，其余收进默认折叠的「高级设置 ▸」。
- **移除保护**：「保护文件夹」列表里每个目录旁都有 `✕ 移除`，点它会问你历史记录怎么处理
  （一起删 / 只移出保留历史 / 取消），**磁盘上的文件永远不动**。
- **数据放哪个盘**：设置 → 存储位置 →「改到别的文件夹…」，历史数据与运行日志都会写到那里（重启生效）；
  同时提供「打开当前位置」与「改回默认」。
- **能删记录**：历史页可以删单条记录；设置页可以清空当前范围的变化记录，
  也可以**清空全部历史数据**（连恢复点与内容库一起清，真正把磁盘空间还回去）。
  三者都不会改动磁盘上的原始文件。
- **滚动条**：界面不显示长条，一律用鼠标滚轮上下滚（隐藏滚动条但保留滚动能力）。

> 原则：**功能可以很多，UI 必须小。** 大卡片、大圆角、大留白、Hero 区域一律不用。

### 恢复的三个独立概念

| 概念 | 由谁决定 |
|---|---|
| **来源状态** | `时间点 [▼]` —— 决定下面浏览哪个历史状态 |
| **目标状态** | `恢复到 [▼]` —— 默认「当前状态」，也可选另一个时间点 |
| **恢复选择集合** | 面板里的迷你文件浏览器 —— 从来源状态里挑文件；换时间点/换目录都不会丢 |

时间点只是"浏览哪个历史状态"的入口；**真正被执行恢复的，是用户自己挑出来的那个集合**。

## 2. 技术栈（受本机实测约束决定）

| 层 | 选择 | 为什么 |
|---|---|---|
| 语言/运行时 | **C# / .NET 8**（`net8.0` + `net8.0-windows`） | 自带 WPF 引用包，可**完全离线**编译；SDK 位置用 `-DotnetPath` 或 `LR_DOTNET` 指定，仓库里不写死任何本机路径 |

| 文件监听 | **`ReadDirectoryChangesW` + 重叠 I/O**（自研） | `FileSystemWatcher` 溢出时**不告知上层**，对本项目是致命的 |

| 进程归属 | 候选进程 + 内核句柄探测（尽力而为） | 实测跨进程 `PROCESS_DUP_HANDLE` **基本被系统拒绝**，如实降级 |

## 4. 已实现的能力（都是真跑的，不是 UI 演示）

### 4.1 受保护范围
- 用户**主动选择**一个或多个文件夹；默认**不监控任何位置**。
- 每个目录可：暂停保护 / 恢复保护 / 移除保护 / 立即创建恢复点 / **重新扫描补齐** / **取消扫描**。
- **添加目录不会卡界面**：登记与监听是瞬间完成的，耗时的首次基线扫描放在后台，
  并先做一次**规模评估**（只枚举、不读内容，数十万文件的目录实测约 14 秒）把
  「多少文件 / 多大 / 预计多久 / 会占多少空间 / 哪些文件能恢复」如实告诉用户，由用户决定是否开始。
- 扫描期间界面完全可用，**随时可取消**；取消后已扫描的部分有效，
  点「重新扫描补齐」会跳过已扫描过的文件继续（这是"可续扫"）。
- 基线扫描完成前建立的恢复点会被标记为「内容不完整」并给出原因，避免用户误用。
- 拒绝把程序自己的数据目录加入保护范围（否则恢复会破坏历史库本身）。

### 4.1b 保护模式（决定"能否恢复内容"）
三种模式，UI 里写明代价与能力，由用户选择：

| 模式 | 行为 | 实测代价（数十万文件 / 数十 GB 的目录） |
|---|---|---|
| **完整内容** | 留存所有文件的历史内容 | ≈110 文件/秒；历史占用最高≈源目录大小 |
| **智能留存**（默认） | 只留存小于阈值（默认 4MB）的文件内容，大文件只记事实 | 兼顾两者；配置/代码/文档目录基本全覆盖 |
| **只记录变化** | 只记录"哪个文件何时发生了什么变化"，不留存内容 | ≈3500 条/秒、占用 0；**无法恢复内容**（UI 明确标注） |

> 这组数字来自对真实目录的实测，不是估算。

### 4.2 监听与事件（真 `ReadDirectoryChangesW`）
- 识别：**创建 / 修改 / 删除 / 重命名 / 移动**（另含"瞬时变化"，默认在时间线折叠）。
- **事件去重与合并**：同一路径同一动作 120ms 内的重复通知直接吃掉；同路径连续修改合并成一条并记录合并次数。
- **延迟确认**：等到文件"稳定"再采集内容，避免读到写了一半的文件。
- **重命名配对**：`OLD_NAME` + `NEW_NAME` 配对；目标已存在则归类为"修改"而不是"创建"。
- **编辑器原子替换**：临时文件被改名为正式文件时，只记录正式文件的变化，不产生虚假的新建/删除。
- **排除规则**：`node_modules`、`.git`、`*.tmp` 等降级为折叠事件（事实留下，但不干扰判断）。
- **缓冲区溢出**：内核报告溢出时**立刻告知并触发全量重扫**，绝不假装没发生。

### 4.3 存储（增量，不复制整个文件夹）
- **内容寻址存储**：SHA-256 寻址，相同内容只存一份（A→B→A 只占一份空间）。
- **快照 = 完整清单**：每个快照都能**独立于事件日志**用于恢复；增量只体现在"与父快照相比多出的那几行"。
- **崩溃安全**：WAL + `synchronous=FULL` + 原子写（临时文件 → 校验哈希 → 原子改名）+ 启动 `integrity_check`。
- **内容索引可重建**：磁盘上的对象文件是权威，索引损坏可从磁盘重建。

### 4.4 首页 / 历史 / 恢复（普通用户视角）

**首页**只回答三个问题：现在在保护什么、最近发生了什么、出问题了怎么办。
没有保护任何文件夹时，首页就是一屏"你的文件后悔药 / ＋ 选择要保护的文件夹"，
不展示保护模式、保留天数、清理计划这些后台设置。

**历史**（原"时间线"）回答"之前发生过什么"：

- 左边是一行一条的变化记录（时间 / 创建·修改·删除 / 路径 / 大小）。
- 中间把相邻 5 分钟内发生的变化合成一段（"今天 13:58 · 新建 5 个 · 修改 3 个 · 删除 4 个"），
  普通用户靠它才能对得上"我刚才那次操作到底动了什么"。
- 右边是选中那一条的详细情况：先是人话（什么时候、干了什么、能不能回到变化前），
  末尾才是给排查用的技术细节（可能相关的程序、内容指纹、记录方式）。

**恢复**是固定三步，页头一直显示进度：

```
① 选择时间  ›  ② 看会改什么  ›  ③ 确认恢复
```

- 第一步只列"今天 11:47 / 昨天 10:15"这样的人话时间点（不用滑条、不用看时间戳）。
- 第二步给出"回到 X 后会发生什么"，是逐条动作还是差异统计都会如实说明。
- 第三步把**具体会动哪些文件**列出来（动作 / 哪个文件 / 大小 / 能不能做），
  再问"确认恢复吗"，并写明"恢复前会自动保存当前状态""恢复错了可以一键撤销"。
- 完成后进入完成页：绿色"✓ 已恢复到 今天 11:32" + 红框里的**「撤销这次恢复」**按钮。

### 4.4c 时间线 / 对比 / Diff（内部能力，位置不变）
- 时间线按天分组，显示时间、操作徽标、路径、**关联进程（按置信度如实措辞）**、大小、合并次数。
- **时间点选择用列表，不用滑条**：早期版本在时间线顶部放了一条 Slider 选恢复点，
  实测**不可用**——所有时间点挤成一个点、点同一像素两次会选中不同时间点、
  也没有任何标签说明哪一段是哪个时刻，结果是"选不到想恢复的那个时间点"。
  现已改为一行一个时间点的列表，点哪行就是哪行。
- **状态对比**：选中时间点 → 与当前状态对比 → 新增 / 删除 / 修改 / 重命名 分类计数。
  对比与预览的结果都渲染在「恢复」页，因此按下这两个按钮会**自动切到「恢复」页**，
  不再出现"点了没反应"（结果其实在看不见的另一页）。
- **文本 Diff**：行级 + **行内字符区间**（用 `«…»` 标出到底改了哪几个字符）。
- **二进制**：绝不强行做文本 Diff，只给大小 / 哈希 / 时间 / 来源。
- **时间一律按本地时间显示**：数据库里所有时间列都存 UTC ticks，
  读取时统一由 UTC 还原成本地时间。早期版本把 `ts_local` 直接当本地时间用，
  导致界面显示的时刻比真实发生时刻差一个时区（UTC+8 下差 8 小时），
  并且会让"按本地时间反查快照"整条链路失效（见第 7 节与第 7.1 节）。

### 4.5 恢复（六条硬规则，每条都有对应代码）
1. **先预览后执行**：预览与执行分离，执行时校验**预览指纹**。
2. **执行前必有安全点**：先对当前状态做完整快照；任何一个文件内容取不到就**中止恢复**。
3. **只做差异**：绝不整目录覆盖，每一步都能对应预览里的一条。
4. **冲突即跳过**：执行时磁盘内容与"预览时看到的内容"不一致 → 跳过并如实报告，**绝不静默覆盖**。
5. **逐步记账**：每一步的执行前内容写入 CAS 并落库，崩溃后可判断实际做到哪一步。
6. **恢复本身可撤销**：撤销 = 以"恢复前安全点"为目标再做一次恢复，因此同样可预览、可追踪、可再次撤销。

### 4.5b 恢复点的自定义管理
- **删除单个恢复点**：可删中间的任意恢复点，**三条硬保护**会拒绝并给出原因——
  ① 正被某次恢复引用的（删了那次恢复就无法撤销）；
  ② 该范围最新的恢复点（删了时间线就失去当前状态锚点）；
  ③ 唯一的基线。
- **加/改备注**：给恢复点起名，例如「升级前」「发给客户之前」。
- **批量清理旧自动恢复点**：按保留天数清理，手动点 / 基线 / 恢复前安全点一律保留。
- **恢复记录逐条可撤销**：每条成功完成的恢复都带一个「撤销」按钮，
  不能撤销时按钮位置会写明原因（"已经撤销过了"/"没有安全点"/"未成功完成"），不让用户对着灰按钮猜。

### 4.6 空间管理
- 显示：历史数据占用 / 保护范围大小 / 历史版本数 / 去重节省 / 上限 / 磁盘剩余。
- 策略：保留天数、最大占用、单文件留存上限、空间不足自动回收。
- **铁律**：被任何快照引用的内容**永不删除**；自动清理只回收"没有被任何恢复点引用"的对象 —— 所以无论怎么清理，"恢复到某个历史时间点"这个能力都不会失效。
- 恢复点（基线 / 手动 / 恢复前安全点）默认**不自动清理**。

## 7. 已知限制（如实记录，不粉饰）

| 限制 | 说明 |
|---|---|
| 进程归属精度 | 跨进程句柄枚举实测基本被系统拒绝（281 个进程中仅 2 个可打开），因此绝大多数事件只能给"该时刻附近活跃的进程" |
| 停机期间的变化 | 用文件系统 mtime 作为事实依据，多次修改会合并成一次；被创建又删除的路径无法发现 |
| 超大文件 | 超过留存上限（默认 64MB）只记录变化事实，不保存内容，并在事件与 UI 中**明确标注不可恢复** |
| GBK 等 ANSI 文本 | .NET Core 默认不带代码页编码器，按本地 ANSI 处理，可能显示为乱码（但不会伪装成正确中文） |
| 二进制 Diff | 不做文本比较（设计如此），只给元数据核对 |
| 时间点列表高度 | 时间线上的时间点列表高度固定（约 5 行），时间点很多时需要滚动；下一轮考虑改成可调或分组 |
| 恢复页时间点上限 | 恢复页一次最多列出**最近 300 个**时间点。超过 300 个有效历史时，更早的恢复点数据库里有、CLI 也能访问，但界面上够不到 —— 未来需要「加载更早 / 分页 / 搜索」三者之一来补齐 |

## 数据与隐私

> 这一节回答一个问题：**这个软件会不会把不该给人看的东西暴露出去？**
> 下面每一条都是对源码与编译产物实际检查后得出的结论。

### 它不联网

| 检查 | 方法 | 结果 |
|---|---|---|
| 源码调用 | 全源码搜索 `HttpClient` / `System.Net` / `WebClient` / `Socket` | **0 处**（6 处 `http://` 全是 XAML 命名空间声明） |
| 编译产物 | 读 `LastRegret.dll` 的程序集引用表 | `System.Net.Http` / `Sockets` / `Primitives` / `Requests` / `WebClient` **全部未引用** |

也就是说：**程序集层面就没有网络库可调用**，不存在"偷偷上传"的可能。
没有统计、没有埋点、没有崩溃上报、没有第三方 SDK（零 NuGet 依赖）。

### 它存什么、存在哪

| 项 | 位置 | 内容 |
|---|---|---|
| 历史数据库 | `%LOCALAPPDATA%\LastRegret\data\events.db` | 被保护目录的**完整路径**、变化记录、恢复点、文件索引 |
| 内容库 | `%LOCALAPPDATA%\LastRegret\data\objects.db` + `store\` | 被保护文件的**内容副本**（按内容哈希去重） |
| 设置 | `%LOCALAPPDATA%\LastRegret\data\*` + `storage.json` | 只有配置阈值与保护模式，**没有任何凭据** |
| 崩溃日志 | `%LOCALAPPDATA%\LastRegret\data\logs\crash.log` | 异常堆栈；**本机路径已自动打码** |

- 都不加密（普通 SQLite 文件），同机其他进程可读 —— 这是本机工具的常态，但不该被误解成"加密存储"。
- **没有密码、没有 token、不写注册表、不设开机自启**（源码级取证）。
- 界面「设置」页直接显示数据目录，并提供**打开数据目录 / 打开日志目录**两个按钮 ——
  你随时能自己去看里面到底有什么。
- 想彻底清干净：「设置」页有**清空全部数据并移除保护范围**，一键回到"从没用过"的状态。
  **磁盘上的原始文件不会被删除或修改。**

### 日志里的路径会打码

这个程序每天操作文件系统，异常消息天然带着你的真实路径。写盘前会统一收敛：

```
示例：
C:\Users\me\Documents\Reports\report.docx   ->   C:\Users\me\…\report.docx
C:\notes.txt                                 ->   C:\notes.txt     （层级本来就浅，原样保留）
```

保留盘符与末级文件名（否则你自己也没法按日志定位问题），中间层级全部省略。
崩溃弹窗里也明确写了这一点，方便你放心把日志发给开发者。

### 卸载

本程序是绿色免安装的（解压即用），**没有安装程序，所以也没有卸载程序**：

1. 删掉解压出来的文件夹即可（程序本体）。
2. 如果连历史数据一起不要了，删 `%LOCALAPPDATA%\LastRegret`；
   或者删之前先在「设置」页点**清空全部数据**（两种方式等效）。
3. 注册表与开机自启项**都没有写过**，无需清理。

> ⚠️ 反过来注意：**删掉 `%LOCALAPPDATA%\LastRegret` 就等于丢掉了全部保护登记与历史**。
> 换机器或重装系统前，先备份这个目录。
